# BoSo-frontend

K-패스·기후동행카드 등 교통 정책 요약, 개인별 To-Do, AI 챗봇을 제공할 BoSo의 프론트엔드입니다. 단일 HTML 제출을 위해 HTML + CSS + Vanilla JavaScript로 전환했습니다.

공통 레이아웃·인증·단일 HTML 생성에 이어 내 정보 조회와 교통 정보 수정·저장·오프라인 프로필 시연을 구현했습니다. 정책·To-Do·챗봇·알림 기능은 후속 작업입니다.

## 실행

Node.js 기준 버전은 `.nvmrc`의 22.14.0이며 npm 10 이상을 사용합니다. 프론트엔드 루트에서 실행합니다.

```powershell
npm.cmd ci
npm.cmd run dev
```

`http://localhost:5173`에서 확인합니다. 수정 후 브라우저를 새로고침하고 종료는 Ctrl+C입니다. macOS/Linux에서는 npm을 사용합니다. 포트 충돌 시 자동 변경하지 않습니다.

## 검증·빌드·제출

```powershell
npm.cmd run check
npm.cmd run preview
```

check는 ESLint → Node 내장 테스트 → 통합 빌드 → Git 공백 검사를 실행합니다. preview는 빌드 파일을 `http://localhost:4173`에서 보여줍니다. 빌드만 하려면 `npm.cmd run build`를 사용합니다.

**제출 파일은 `dist/BoSo.html` 하나**입니다. CSS·일반 JS·PNG를 포함하므로 복사 후 더블클릭으로 열 수 있습니다. 열람자에게 Node.js나 node_modules는 필요 없습니다. 개발용 index.html과 과거 Vite 출력은 제출하지 않습니다.

현재 결과물에서 계정 시연과 메뉴 이동을 확인할 수 있습니다. 최종 핵심 서비스 전체가 완성됐다는 뜻은 아니며 후속 기능 개발과 통합 검증이 필요합니다.

## 최소 구조

```text
index.html                 공통 레이아웃·화면 template·공개 설정
src/app.js                 해시 이동·DOM 화면 조립
src/services.js            API·실행 모드·메모리 상태
src/auth.js                인증 계약·세션·오프라인 계정 시연
src/profile.js             프로필 조회·수정·시연 저장·화면 연결
src/styles.css             기존 디자인·공통 UI·반응형 스타일
src/assets/                기존 캐릭터 PNG 2개
scripts/build.mjs          단일 HTML 생성
scripts/serve.mjs          로컬 개발·preview 서버
tests/foundation.test.mjs   API·모드·상태·통합 파일 검증
```

프레임워크·Router·번들러는 사용하지 않습니다. ESLint만 개발 의존성으로 유지하고 테스트·빌드는 Node 내장 기능을 사용합니다. 홈·인증·내 정보 외의 서비스 메뉴는 준비 안내입니다.

## 실행 모드와 API

index.html의 boso-config에 공개 설정을 둡니다.

```json
{"mode":"auto","apiBaseUrl":"http://localhost:8000"}
```

auto는 HTTP(S)에서 서버 연동 모드, file://에서는 시연 모드입니다. demo로 명시할 수도 있습니다. 파일 직접 실행은 live 설정에도 항상 시연 모드이며 네트워크 요청을 보내지 않습니다. 계정·프로필 시연은 각 모듈에서 처리하고 그 밖의 시연 API는 DEMO_NOT_IMPLEMENTED를 반환합니다. 서버 연결 실패를 시연 성공으로 바꾸지 않습니다. 하단의 모드 표시는 실제 연결 성공을 뜻하지 않습니다.

HTTP 클라이언트는 쿠키 전달(credentials: include), JSON·오류·취소 처리를 지원합니다. 보호 API는 `BoSo.auth.request(path, options)`를 사용하면 Bearer 전달과 한 번의 인증 갱신·재시도를 적용합니다. 공개 API는 `BoSo.services.request`를 사용합니다.

## 로그인·회원가입 확인

`#/login`, `#/signup`에서 이용합니다. 서버 계약에 맞춰 이메일을 소문자·양끝 공백 제거로 정규화하고 비밀번호는 공백을 포함해 15~128자로 검증합니다. 회원가입 후 로그인하며, 보호 메뉴로 이동하다 로그인했다면 원래 메뉴로 돌아갑니다. 현재 보호 대상은 내 정보·To-Do·챗봇·알림입니다. 정책 메뉴와 홈은 공개입니다.

- **파일 시연**: 로그인 화면의 **시연 계정으로 둘러보기**를 누르거나 예시 이메일로 회원가입한 뒤 로그인합니다. 실제 서버 계정을 만들지 않습니다. 계정·세션은 메모리에만 있어 새로고침하면 초기화됩니다. 등록한 시연 비밀번호는 무작위 salt와 PBKDF2 digest로 비교하고 평문 저장하지 않습니다. Web Crypto 미지원 브라우저에서는 미리 제공한 시연 계정을 사용합니다.
- **실제 인증**: FastAPI·DB 및 서버의 인증 설정이 준비된 상태에서 localhost:5173으로 실행합니다. `/api/v1/auth/signup`, `/login`, `/me`, `/csrf`, `/refresh`, `/logout`의 실제 계약을 사용합니다. 새로고침 시 쿠키로 CSRF 확인 → 갱신 → 사용자 확인을 수행합니다.

access token·CSRF 값은 메모리에만 보관합니다. refresh 쿠키는 서버가 관리합니다. 토큰 만료 또는 401 발생 시 같은 탭의 동시 갱신을 합치고 업무 요청을 최대 한 번 재시도합니다. 갱신 후 사용자 식별자가 바뀌면 기존 인증을 해제합니다. 여러 탭 간 갱신 잠금은 제공하지 않으므로 동시 갱신 시 서버의 재사용 감지로 재로그인이 필요할 수 있습니다. 로그아웃 연결 실패를 성공으로 표시하지 않으며 재시도할 수 있습니다. 인증 HTTP 요청의 기본 대기 제한은 지원 브라우저에서 15초입니다.

실제 회원 인증·DB·Gemini는 FastAPI와 네트워크가 필요합니다. 파일 origin은 null이므로 현재 서버 Origin·CORS·쿠키 정책과 맞지 않습니다. 서버 보안을 완화하지 않고 HTTP(S)에서 실제 연동을 검증합니다. 로컬 API 개발에는 서버 기본 CORS와 일치하는 localhost:5173을 사용합니다. 127.0.0.1 또는 preview의 4173은 별도 origin이므로 기본 허용 대상이 아닙니다. 오프라인 제출은 명시적인 샘플 데이터로 핵심 흐름을 구현해야 합니다.

API 주소는 경로 없는 HTTP(S) origin만 허용합니다. 설정은 전부 공개되므로 DB 비밀번호·JWT 서명 키·Gemini 키를 넣지 않습니다. Vite .env.example은 제거했고 .env 자동 로딩은 없습니다. 기존 개인 .env는 수정하지 않습니다. 설정 변경 후 재빌드하세요.

## 내 정보·교통 정보 확인

로그인 후 `#/profile`에서 이메일·생년월일·나이·거주 지역·보유 교통카드·주요 이동 수단을 조회합니다. **교통 정보 수정 → 저장하기**로 변경하고 **취소**는 기존 저장값을 유지합니다. 일부 항목을 비우거나 선택을 해제해 저장할 수도 있습니다.

- 실제 API: `GET /api/v1/me`, `GET /api/v1/me/options`, `PATCH /api/v1/me`. Bearer 인증을 적용하며 선택 항목·나이·기준일·입력 완성 여부는 서버 응답을 사용합니다. 이메일·사용자 ID는 수정 요청에 넣지 않습니다.
- 생년월일은 1900-01-01부터 기준일 사이이며, 기타 / 이용 카드 없음은 다른 카드와 함께 선택하지 않습니다. K-패스·기후동행카드와 버스·지하철은 복수 선택할 수 있습니다.
- 파일 시연은 같은 계약의 로컬 예시 선택 항목을 사용합니다. 프로필만 `boso.demo.profile.v1.<사용자 ID>` 키로 현재 브라우저에 저장하고, 인증 토큰·이메일·비밀번호는 저장하지 않습니다. **시연 교통 정보 초기화**는 현재 시연 계정의 프로필만 삭제합니다.
- 저장소 차단·손상·용량 부족 시 현재 창의 메모리에서 유지하며 안내 문구로 구분합니다. 파일 위치나 브라우저가 바뀌면 저장 정보가 공유되지 않을 수 있습니다. 새로고침하면 로그인은 해제되므로 **시연 계정으로 둘러보기**로 다시 진입하세요. 새로 가입한 시연 계정 자체는 새로고침 시 초기화됩니다.
- 실제 서버의 프로필은 브라우저에 영속 저장하지 않습니다. 조회·저장 실패는 성공으로 표시하지 않으며, 재조회로 서버의 저장 여부를 확인할 수 있습니다. 화면 이동 시 요청을 취소하고 계정 변경 후의 오래된 응답을 폐기합니다.
