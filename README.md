# BoSo-frontend

K-패스·기후동행카드 등 교통 정책 요약, 개인별 To-Do, AI 챗봇을 제공할 BoSo의 프론트엔드입니다. 단일 HTML 제출을 위해 HTML + CSS + Vanilla JavaScript로 전환했습니다.

공통 화면·인증·프로필·정책·To-Do·챗봇·알림의 오프라인 시연을 제공합니다. To-Do·챗봇은 확인한 서버 계약의 클라이언트를 포함합니다. 실제 정책·알림 HTTP 연동은 서버 계약 확정이 필요합니다.

## 실행

Node.js 기준 버전은 `.nvmrc`의 22.14.0이며 npm 10 이상을 사용합니다. 프론트엔드 루트에서 실행합니다.

```powershell
npm.cmd ci
npm.cmd run dev
```

`http://localhost:5173`에서 확인합니다. 수정 후 브라우저를 새로고침하고 종료는 Ctrl+C입니다. macOS/Linux에서는 npm을 사용합니다. 포트 충돌 시 자동 변경하지 않습니다.

## 검증·빌드·제출

```powershell
npm.cmd run check
npm.cmd run preview
```

check는 ESLint → Node 내장 테스트 → 통합 빌드 → Git 공백 검사를 실행합니다. preview는 빌드 파일을 `http://localhost:4173`에서 보여줍니다. 빌드만 하려면 `npm.cmd run build`를 사용합니다.

**제출 파일은 `dist/BoSo.html` 하나**입니다. CSS·일반 JS·PNG를 포함하므로 복사 후 더블클릭으로 열 수 있습니다. 열람자에게 Node.js나 node_modules는 필요 없습니다. 개발용 index.html과 과거 Vite 출력은 제출하지 않습니다.

시연은 로그인 화면의 시연 계정 진입을 사용하면 됩니다. 아래 제출 확인 절차를 따르세요. 실제 DB·Gemini 통합과 운영 배포는 별도 검증이 필요합니다.

## 최소 구조

```text
index.html                 공통 레이아웃·화면 template·공개 설정
src/app.js                 해시 이동·DOM 화면 조립
src/services.js            API·실행 모드·메모리 상태
src/auth.js                인증 계약·세션·오프라인 계정 시연
src/profile.js             프로필 조회·수정·시연 저장·화면 연결
src/policies.js            정책 서비스·검색·상세·홈 소식·시연 자료
src/styles.css             기존 디자인·공통 UI·반응형 스타일
src/assets/                기존 캐릭터 PNG 2개
scripts/build.mjs          단일 HTML 생성
scripts/serve.mjs          로컬 개발·preview 서버
tests/foundation.test.mjs   API·모드·상태·통합 파일 검증
```

프레임워크·Router·번들러는 사용하지 않습니다. ESLint만 개발 의존성으로 유지하고 테스트·빌드는 Node 내장 기능을 사용합니다. To-Do·챗봇·알림 메뉴는 준비 안내입니다.

## 실행 모드와 API

index.html의 boso-config에 공개 설정을 둡니다.

```json
{"mode":"auto","apiBaseUrl":"http://localhost:8000"}
```

auto는 HTTP(S)에서 서버 연동 모드, file://에서는 시연 모드입니다. demo로 명시할 수도 있습니다. 파일 직접 실행은 live 설정에도 항상 시연 모드이며 네트워크 요청을 보내지 않습니다. 계정·프로필·정책 시연은 각 모듈에서 처리하고 그 밖의 시연 API는 DEMO_NOT_IMPLEMENTED를 반환합니다. 서버 연결 실패를 시연 성공으로 바꾸지 않습니다. 하단의 모드 표시는 실제 연결 성공을 뜻하지 않습니다.

HTTP 클라이언트는 쿠키 전달(credentials: include), JSON·오류·취소 처리를 지원합니다. 보호 API는 `BoSo.auth.request(path, options)`를 사용하면 Bearer 전달과 한 번의 인증 갱신·재시도를 적용합니다. 공개 API는 `BoSo.services.request`를 사용합니다.

## 로그인·회원가입 확인

`#/login`, `#/signup`에서 이용합니다. 서버 계약에 맞춰 이메일을 소문자·양끝 공백 제거로 정규화하고 비밀번호는 공백을 포함해 15~128자로 검증합니다. 회원가입 후 로그인하며, 보호 메뉴로 이동하다 로그인했다면 원래 메뉴로 돌아갑니다. 현재 보호 대상은 내 정보·To-Do·챗봇·알림입니다. 정책 메뉴와 홈은 공개입니다.

- **파일 시연**: 로그인 화면의 **시연 계정으로 둘러보기**를 누르거나 예시 이메일로 회원가입한 뒤 로그인합니다. 실제 서버 계정을 만들지 않습니다. 계정·세션은 메모리에만 있어 새로고침하면 초기화됩니다. 등록한 시연 비밀번호는 무작위 salt와 PBKDF2 digest로 비교하고 평문 저장하지 않습니다. Web Crypto 미지원 브라우저에서는 미리 제공한 시연 계정을 사용합니다.
- **실제 인증**: FastAPI·DB 및 서버의 인증 설정이 준비된 상태에서 localhost:5173으로 실행합니다. `/api/v1/auth/signup`, `/login`, `/me`, `/csrf`, `/refresh`, `/logout`의 실제 계약을 사용합니다. 새로고침 시 쿠키로 CSRF 확인 → 갱신 → 사용자 확인을 수행합니다.

access token·CSRF 값은 메모리에만 보관합니다. refresh 쿠키는 서버가 관리합니다. 토큰 만료 또는 401 발생 시 같은 탭의 동시 갱신을 합치고 업무 요청을 최대 한 번 재시도합니다. 갱신 후 사용자 식별자가 바뀌면 기존 인증을 해제합니다. 여러 탭 간 갱신 잠금은 제공하지 않으므로 동시 갱신 시 서버의 재사용 감지로 재로그인이 필요할 수 있습니다. 로그아웃 연결 실패를 성공으로 표시하지 않으며 재시도할 수 있습니다. 인증 HTTP 요청의 기본 대기 제한은 지원 브라우저에서 15초입니다.

실제 회원 인증·DB·Gemini는 FastAPI와 네트워크가 필요합니다. 파일 origin은 null이므로 현재 서버 Origin·CORS·쿠키 정책과 맞지 않습니다. 서버 보안을 완화하지 않고 HTTP(S)에서 실제 연동을 검증합니다. 로컬 API 개발에는 서버 기본 CORS와 일치하는 localhost:5173을 사용합니다. 127.0.0.1 또는 preview의 4173은 별도 origin이므로 기본 허용 대상이 아닙니다. 오프라인 제출은 명시적인 샘플 데이터로 핵심 흐름을 구현해야 합니다.

API 주소는 경로 없는 HTTP(S) origin만 허용합니다. 설정은 전부 공개되므로 DB 비밀번호·JWT 서명 키·Gemini 키를 넣지 않습니다. Vite .env.example은 제거했고 .env 자동 로딩은 없습니다. 기존 개인 .env는 수정하지 않습니다. 설정 변경 후 재빌드하세요.

## 내 정보·교통 정보 확인

로그인 후 `#/profile`에서 이메일·생년월일·나이·거주 지역·보유 교통카드·주요 이동 수단을 조회합니다. **교통 정보 수정 → 저장하기**로 변경하고 **취소**는 기존 저장값을 유지합니다. 일부 항목을 비우거나 선택을 해제해 저장할 수도 있습니다.

- 실제 API: `GET /api/v1/me`, `GET /api/v1/me/options`, `PATCH /api/v1/me`. Bearer 인증을 적용하며 선택 항목·나이·기준일·입력 완성 여부는 서버 응답을 사용합니다. 이메일·사용자 ID는 수정 요청에 넣지 않습니다.
- 생년월일은 1900-01-01부터 기준일 사이이며, 기타 / 이용 카드 없음은 다른 카드와 함께 선택하지 않습니다. K-패스·기후동행카드와 버스·지하철은 복수 선택할 수 있습니다.
- 파일 시연은 같은 계약의 로컬 예시 선택 항목을 사용합니다. 프로필만 `boso.demo.profile.v1.<사용자 ID>` 키로 현재 브라우저에 저장하고, 인증 토큰·이메일·비밀번호는 저장하지 않습니다. **시연 교통 정보 초기화**는 현재 시연 계정의 프로필만 삭제합니다.
- 저장소 차단·손상·용량 부족 시 현재 창의 메모리에서 유지하며 안내 문구로 구분합니다. 파일 위치나 브라우저가 바뀌면 저장 정보가 공유되지 않을 수 있습니다. 새로고침하면 로그인은 해제되므로 **시연 계정으로 둘러보기**로 다시 진입하세요. 새로 가입한 시연 계정 자체는 새로고침 시 초기화됩니다.
- 실제 서버의 프로필은 브라우저에 영속 저장하지 않습니다. 조회·저장 실패는 성공으로 표시하지 않으며, 재조회로 서버의 저장 여부를 확인할 수 있습니다. 화면 이동 시 요청을 취소하고 계정 변경 후의 오래된 응답을 폐기합니다.

## 정책 화면 확인

`index.html` 또는 `dist/BoSo.html`을 직접 열어 홈의 **바뀐 정책 확인하기 → 전체 정책 → 정책 제목**으로 이동합니다. 전체 정책은 로그인 없이 이용할 수 있습니다. 검색·필터는 접힌 **정책 검색·필터**에서 펼쳐 사용합니다. 카테고리·적용 상태·페이지와 탭 선택은 해시에 남아 상세의 목록 버튼·새로고침에서 유지됩니다.

홈은 최종 와이어프레임의 파란 안내 배너·분홍/파랑 카드 두 개·하단 AI 안내 배치로 구성했습니다. 정책 화면은 **내 관련 소식 / 전체 정책** 탭, 왼쪽 변경 전후 카드와 오른쪽 분홍색 **내 영향 확인** 패널을 사용합니다. 내 관련 소식은 시연 모드에서 로그인한 계정의 등록 카드와 같은 분류의 예시를 보여 주며 정책 자격 판정이 아닙니다. 카드 미등록·비로그인 상태는 안내를 표시하고 임의의 보유 카드나 추천 결과를 만들지 않습니다. 모바일에서는 두 열을 세로로 배치합니다.

상세에는 미리 작성한 요약 예시, 본문, 확인 조건, 변경 전후, 적용 기간·마감일, 출처 확인일을 표시합니다. 시연 자료는 5개이며 K-패스 안내는 두 버전 비교, 기후동행카드 안내는 요약·이전 버전 없음, 요금·지원 안내는 기간 만료·종료 상태를 보여 줍니다. 실제 정책·혜택·검수 결과가 아니며 AI를 호출하지 않습니다. 예시 출처 URL은 외부 연결을 제공하지 않습니다.

**실제 연동 대기:** 현재 서버의 `app/modules/policies/router.py`에는 등록된 엔드포인트가 없습니다. `docs/policy-data.md`에서도 HTTP 조회는 후속 `feat/policy-api`로 명시합니다. 내부 정책 모델·서비스를 HTTP 응답 계약으로 간주하지 않았으며, 목록·상세·변경 이력·AI 요약 경로를 추측하지 않았습니다. HTTP(S)의 live 모드에서는 준비 안내를 표시하며 정책 API 요청이나 샘플 대체를 하지 않습니다.

후속 연동에는 목록·검색 조건·정렬·페이지 형식, 정책/버전 ID, 상세·변경 이력 응답, 카테고리 표시값, 요약 생성/조회·실패·출처 계약이 필요합니다. 확정 후 `createPolicies`의 live 경로와 응답 검증을 추가하고 실제 서버·DB·AI 통합을 검증해야 합니다. 현재 시연용 policy_key를 실제 정책 UUID나 HTTP 계약으로 사용하지 마세요.

## 개발 규칙

### 챗봇 전달 단계

src/chat.js는 대화 생성·목록·메시지 조회/전송 API와 시연 대화를 제공한다. 실제 POST에는 UUID request_id와 question, policy_ids만 전송한다. 같은 화면·작업본 메모리에서 같은 질문의 실패 후 재전송은 같은 request_id를 사용하며 자동 네트워크 재시도는 하지 않는다. 실패 후 질문을 유지하고 다시 불러오기로 저장 여부를 확인할 수 있다. 새로고침을 넘어 요청 ID를 영속 보관하지 않으므로 전송 직후 연결이 끊겼다면 대화 기록을 먼저 확인한다.

실제 질문은 서버 저장·외부 AI 전송 가능성을 입력창에서 안내한다. 실제 대화 원문은 localStorage에 저장하지 않는다. 시연 대화만 계정별 저장하며 미리 작성한 답변과 실제 AI 답변을 구분한다. source URL은 HTTPS 형식을 확인하고 안전한 새 창 링크로 표시하며, 관련 할 일은 해당 ID의 상세로 연결한다. 실제 정책 HTTP 조회·실제 Gemini 호출 검증은 이 전달 단계에서 수행하지 않았다.

To-Do는 로그인 후 `#/todos`에서 조회·필터·상세·완료/취소·진행 현황을 제공합니다. 실제 모드는 `/api/v1/todos` 목록·summary·상세·PATCH와 명시적인 POST sync를 사용합니다. GET으로 할 일을 생성하지 않습니다. 프로필 저장 후 sync를 요청하며 실패해도 이미 저장된 프로필을 실패로 되돌려 표시하지 않습니다.

시연 목록은 정책 판정과 무관한 명시적 예시 3개이며 사용자별로 완료·단계 체크를 저장합니다. 세부 단계 체크는 시연 전용이고 실제 서버에는 완료 여부만 전송합니다. 실제 정책 HTTP 조회가 없으므로 실제 To-Do의 정책 UUID를 시연 정책 키로 바꾸거나 잘못된 정책 링크를 만들지 않습니다. 브라우저 저장이 차단되면 현재 창에서만 유지합니다.

# 알림 화면

`#/notifications`에서 전체·안 읽음·읽음 필터, 개별/모두 읽음, 정책·할 일 이동을 제공합니다. 헤더 배지는 현재 계정의 안 읽은 개수를 표시합니다. 현재 백엔드 알림 라우터에 HTTP 계약이 없어 이 기능은 **시연 전용**입니다. 실제 모드는 준비 안내를 표시하고 추정 API를 호출하지 않습니다. 이메일·브라우저 푸시·서버 이벤트 수신을 구현한 기능이 아닙니다.
## 제출 확인 절차

`npm.cmd run build` 후 `dist/BoSo.html`만 다른 빈 폴더로 복사하고 인터넷 연결을 끊은 상태에서 더블클릭합니다. Node·웹서버·다른 소스 파일 없이 열려야 합니다.

1. 로그인 → 시연 계정으로 시작합니다. 일반 회원가입도 현재 창에서 시험할 수 있으며 실제 서버 계정은 아닙니다.
2. 내 정보에서 교통 정보를 저장하고 다시 열어 확인합니다.
3. 정책 검색·필터·상세·변경 전후·요약 예시를 확인합니다.
4. To-Do 목록·상세의 단계 체크·완료·완료 취소를 확인합니다.
5. 챗봇에 `할 일 확인`을 입력하고 시연 답변·관련 To-Do 이동을 확인합니다.
6. 알림의 읽음 표시·상단 미확인 수·관련 화면 이동을 확인합니다.
7. 푸터의 `내 시연 기록 초기화`는 확인 후 현재 계정의 교통 정보·할 일·대화·알림만 지우고 로그아웃합니다. 다른 사이트나 다른 계정 저장소를 전체 삭제하지 않습니다.
8. 뒤로가기·새로고침·320/390/768/1440px 폭·Tab 키·외부 네트워크 요청 여부를 확인합니다.

파일 모드의 계정·인증은 새로고침하면 초기화합니다. 시연 데이터 저장은 파일 출처에 대한 브라우저 정책에 따라 현재 창에 한정될 수 있습니다. 사용자별 임의 ID로 구분하므로 새로고침 후 새 계정으로 이전 기록이 복원된다고 보장하지 않습니다. 실제 인증·DB·Gemini는 HTML 내부에 넣지 않으며 HTTP(S) 서비스와 FastAPI에서 처리합니다. 정책·알림 실제 API는 준비 중이고, 챗봇의 시연 답변은 생성 AI 호출 결과가 아닙니다.
