## 협업

A는 기반·인증·사용자 정보·정책을 완성하고 공통 연결 방법과 검증 결과를 B에게 인계한다. B는 To-Do·챗봇·알림과 최종 패키징을 담당한다. API 규격 확인·통합 테스트·오류 수정은 공동 수행하되 각 브랜치 담당을 따른다.

최종 와이어프레임의 화면·동작을 우선하고 PPTX 서비스 흐름과 기존 색상·캐릭터를 참고한다. 기획 원본은 수정하지 않는다. 각 단계는 앞 단계의 develop 통합 뒤 시작한다. 작업 브랜치 → develop → main을 따르며 Git 쓰기는 사용자 요청 범위에서 수행한다.

## 현재 범위와 제출 기준

0번은 공통 화면·이동·API·상태 기반·통합 파일 생성과 규칙 갱신이다. 실제 회원·정책·To-Do·챗봇·알림 및 시연 데이터는 각 후속 단계에서 구현한다.

각 기능 단계에서 서버 없는 샘플 데이터·상태·실패 안내를 함께 구현한다. 시연을 실제 인증·실시간 AI 결과로 표시하지 않는다. 최종적으로 BoSo.html만 별도 위치에 복사해 네트워크 없이 계정 시연 → 프로필 → 정책 → To-Do → 챗봇 → 알림 흐름을 확인한다. 새로고침·뒤로가기·초기화·키보드·320px 이상 모바일을 검증한다.

실제 인증·개인 데이터·Gemini는 HTTP(S)와 서버에서 별도 검증한다. 오프라인 실제 인증·실시간 AI까지 요구한다면 단일 HTML만으로 충족할 수 없으므로 제출 범위 합의가 필요하다.
